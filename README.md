# NOSHASHI

**XRPL intelligence for institutional decisions.**

NOSHASHI helps institutions understand whether XRPL assets and transactions
can move under their policies, whether enough real liquidity exists to
execute the intended operation, and why the system reached its conclusion.
Every analysis produces evidence that can be reviewed and verified.

## One ledger. Three questions.

| | Question | What NOSHASHI does |
|---|---|---|
| **Compliance** | Can this move? | GO, HOLD or NO-GO from a deterministic rule set and your versioned policy, with every rule's result and reason. |
| **Liquidity** | Can this actually exit? | Separates what the order book *quotes* from what its owners can actually *deliver*, simulates the exit against the fillable depth, and joins it to the issuer's freeze rights. |
| **Evidence** | Can we prove why? | A SHA-256 receipt over the decision, the rules and the policy version, bound to the ledger it was read at; re-verifiable, replayable and exportable. |

## How a decision is made

```
XRPL ledger → validate (several public servers must agree)
            → deterministic rules → your policy version
            → GO / HOLD / NO-GO → SHA-256 receipt
            → an authorized person decides
```

The AI assistant (NOSHX) explains results and cites the readings it rests on.
It never issues a decision, never signs, and the deterministic engine wins
when the two disagree. NOSHASHI **only reads** the ledger: there is no code
path that signs or submits a transaction, and it never asks for a key.

## What it does

- **Compliance**: settlement gate; institutional policies (HHI,
  counterparty share, Travel Rule threshold, reserve headroom, strict
  freeze) with value, unit, trigger and effect shown for each; four-eyes
  activation; exceptions with expiry; credentials and permissioned domains
  read from mainnet.
- **Liquidity**: order-book integrity (quoted vs fillable), exit
  simulation, AMM pools, stress schedules.
- **Evidence**: receipts, re-verification, replay at the recorded ledger,
  an institutional report per decision with independent verification
  instructions, audit-trail export with a SHA-256 manifest.
- **Organizations**: roles, row-level security, append-only audit log,
  Compliance API with keys, rate limits and signed webhooks.
- **Executive and Analyst modes**: eight core screens by default; every tool
  one switch or one search away.

## Free tools, no account

- **Issuer authority certificate**: <https://www.noshashi.app/certificate/>.
  Paste any XRPL issuer address to see what that issuer can still do to

## Quick start

Download the latest release (macOS, Windows, Linux):
<https://github.com/Ignosha/noshashi/releases/latest>. Builds are not yet
code-signed, so macOS and Windows will warn on first launch; each release
publishes SHA-256 checksums.

From source:

```bash
npm install
npm run tauri:dev
```

This opens the desktop app against **XRPL mainnet**. There is no testnet
path in the build.

## Development

```bash
npx vite               # web view only, in a browser
npx vitest run         # unit and invariant tests
npx tsc --noEmit       # type check
npm run build          # production web build
npm run check:functions   # Deno type check of the Supabase Edge Functions
npm run tauri:build    # desktop build for this platform
```

Tests use recorded **real mainnet replies**, never invented ledger data.
The website is generated by `npm run site:build` from the code's own facts.

## Architecture

| Layer | Where |
|---|---|
| Desktop app | `src/` (React, Vite), `src-tauri/` (Tauri 2, Rust) |
| Deterministic engine | `src/lib/policy.ts`, `src/lib/desk/` |
| XRPL access | `src/lib/xrpl/` (paced WebSocket reads), `src/lib/net/` (multi-node agreement) |
| Server | Supabase (`supabase/migrations`, `supabase/functions`) |
| Website | `site/` (generated), `api/` (Vercel functions) |
| AI assistant | `src/lib/noshx/`, `src/lib/agent/` |
