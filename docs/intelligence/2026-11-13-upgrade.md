## Implemented safe phase

`/intelligence/rlusd/` and GET `/api/rlusd` reuse the existing static shell/API consolidation. Exact decimal strings and BigInt preserve amounts. XRPL reads pin obligations to one validated ledger; Ethereum checks chain ID and pins decimals/totalSupply to a finalized canonical block. Each source fails independently to unavailable. No fabricated zero or last-good value is substituted.

The dashboard offers user-requested snapshots, explicit source/ledger/observation timestamps, stale labels, per-chain session time-series, exact accessible sample lists, an exact basis-point change threshold preview, issuer/depth/payment links and demo/tester/pilot CTAs. Cache duplicates do not create chart observations. Samples are capped at 24 per chain in memory and disappear when the tab closes. Charts join observations; they do not claim continuous data coverage. No 24-hour delta inferred.

Settlement handoff and regulatory-status views are explicitly prototypes. They do not assert unverified company relationships or load legal rules. Newsroom gets a deep link and an approved-schema stablecoin workflow. Five source-backed candidate drafts are in an owner-only store outside the repository, all NEEDS REVIEW, with no approval tokens. No article manifest changed.

## Security findings and limits

* New endpoint: fixed identities/URLs only, GET only, no caller-selected RPC URL, wallet credentials, writes or transactions. Existing per-instance limiter plus CDN/warm cache and in-flight coalescing bound repeated work. This is not a globally distributed quota.
* Public data only; no private pipeline/database imports. UI source text uses textContent; no remote HTML rendering. Existing CSP remains unchanged.
* `npm audit --omit=dev --json`: zero reported production vulnerabilities. This does not cover Rust/dev dependencies or establish absence of vulnerabilities.
* CI verify jobs explicitly use contents:read; release publishing explicitly uses contents:write. Third-party actions currently use mutable version tags; pinning SHAs is recommended as a separate change.
* GitHub Actions/default permission APIs returned **403 Resource not accessible by integration**. Organization permissions, branch protection, environment approvals and token grants remain unaudited.
* Live Supabase RLS, Cloudflare secret inventory, production credentials, AI-agent grants and production audit-log retention were not verified. No credentials were read, printed, rotated or changed. No counterparty crime/identity score added.

## Setup, budgets and remaining phases

No new keys, dependency, paid service or database is required for the read-only phase. Public RPC availability/terms/limits must be reviewed before institutional production use. XRPL gateway_balances can be disabled by a node; Ethereum EIP-1898 or finalized reads can be unsupported. Both produce honest unavailable states.

Best-case cold snapshot: two XRPL requests plus five Ethereum requests. Five-minute CDN/warm caching shares reads but cannot guarantee a global cap across regions or cold starts. A continuously requested single warm instance could make about 2,016 upstream calls/day (7 × 288). Actual cost depends on hosting plan/traffic; no price guarantee. Generation/image/video cost for this phase: $0; no paid calls. Browser polling: none. Existing newsroom suggestion remains two collection runs per weekday with six-hour minimum; activating a private scheduler requires approval and persistent owner-only storage.

Next reviewable phases: persist timestamped observations with retention and coverage checks; complete mint/burn accounting with treasury reconciliation; venue-specific pool/depth and trade sources; authenticated alert policies, durable deduplication and delivery; source-discovery expansion with verified feed endpoints; assisted writing with claim verification and human approval; live regulatory source/status ingestion with expert review. The attempted official DOJ RSS URL did not return a usable feed, so it was not added. No research scheduler or production alert was enabled.

Manual approval is still required for deployment, article publication, production rules, external notification setup, purchases, merge or outreach. This change is ready for code review, not a claim of complete institutional monitoring.
