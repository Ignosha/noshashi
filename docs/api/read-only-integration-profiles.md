# Read-only XRPL integration profiles

These are evaluation proposals for potential collaboration. Dfns and EXFIL have made no partnership commitment to this work. The current interface is the loopback [Transaction Autopsy API](openapi-autopsy.yaml). An approved isolated evaluator can submit a public XRPL Mainnet transaction hash and receive the corroborated result, ledger reference, available payment destination and delivered amount, source labels, and reason codes. A research receipt can carry the report and its SHA-256 digest for integrity checking. A separately configured local case reviewer can attach an Ed25519 attestation to that digest.

| Potential collaborator | Evaluation | Data boundary | Acceptance check |
| --- | --- | --- | --- |
| Dfns | Attach XRPL evidence to a wallet operator's payment investigation. The operator can reconcile a public transaction hash, destination, issuer, currency and exact delivered amount against an independently held intent or invoice. | Exchange public ledger identifiers and the research result only. Retain wallet ownership and binding to the private intent inside the operator's system. | A recorded partial-payment fixture exposes the delivered amount independently of the requested amount. Conflicting source results produce `UNKNOWN` and the operator's review remains pending. |
| EXFIL | Attach a ledger-pinned observation to an existing threat investigation. The case analyst can compare a public issuer, holder, currency and ledger hash against local AccountRoot and RippleState diagnostics. | Exchange only approved public ledger facts and reason codes. Keep private indicators, sanctions data, analyst identities and investigation notes outside the research interface. | Reproduce a known RippleState observation with both providers. Vary the currency or ledger in a fixture and confirm the mismatched entry is not accepted as evidence. |

The API provides transaction evidence. The AccountRoot and RippleState capabilities run through local diagnostics and are outside the HTTP contract. Both profiles require keyless public ledger reads, exact identifiers and ledger pinning, an explicit unavailable state, and an operator-controlled review decision. The only credential in the current HTTP setup is a local gateway bearer secret. Verify an optional detached attestation against an independently trusted key. It covers the transaction report. A separate optional attestation covers transaction-bound control observations. Provider identity and operator decisions remain outside both signed statements. The proposed evaluations grant no signing, submission, custody, approval or sanctions-screening authority.

The [live smoke](../../scripts/autopsy-live-smoke.mjs) provides a reproducible shared exercise. For payment reconciliation, it checks the exact delivered amount at validated ledger 107,585,451. For ledger-risk review, it reproduces issuer freeze and deep freeze on the public RLUSD fixture at ledger 108,533,744, with separate provider diagnostics. A third example keeps the case on HOLD with synthetic approval snapshots and verifies its transaction attestation with an ephemeral key.

A hosted pilot interface would require tenant-scoped identity and review of event schemas, retention, audit access, availability expectations and approved data fields. External outreach and any exchange of private data require founder approval.
