Rehearsal walkthrough

Open the rehearsal in a browser and expand each step below for its click path and evidence.

  1. Review the recorded SOLO payment Historical

    Open Recorded payment and click Run payment review. Compare the requested amount with the delivered 0.067791435856414 SOLO. Check the issuer, destination and tag findings. Open Capture timestamps to see the archived observations.

    The transaction and destination observations bind to validated ledger 107,585,451. Invoice reconciliation stays on HOLD because the archive has no invoice.

  2. Verify and export the receipt Historical

    Click Verify receipt digest and look for Digest matches. Click Export receipt JSON to save the payload and its SHA-256 digest.

    Recomputing the digest checks the saved payload against the recorded hash. Provider identity and institutional approvals require separate evidence.

  3. Inspect the RLUSD issuer Historical

    Open RLUSD intelligence. Find the Issuer account, XRPL currency code, and control flags at validated ledger 107,586,974.

    Read the network, issuer and currency code together. The snapshot shows controls at that ledger. Concentration is unknown in this reading. Reserve disclosures are a separate source.

  4. Simulate a wallet handoff Simulated

    Open Wallet handoff and click Assess simulated intent. Read the HOLD assessment. Click Simulate new tag requirement and compare the same intent fingerprint with the new NO-GO result.

    The fictional change illustrates how a destination rule can affect a reviewed payment. The Dfns example is hypothetical and uses a mock wallet provider. The wallet provider retains signing and execution in this model.

Run the browser rehearsal offline

Save both files to the same folder while you are online. The archive includes the browser build and the rehearsal dataset.

Download browser archive Download SHA-256 checksum

  1. Check the archive

    From the download folder, check that the file matches the published checksum. On macOS:

    shasum -a 256 -c noshashi-continuity-browser.zip.sha256

    On Linux, run sha256sum -c noshashi-continuity-browser.zip.sha256.

  2. Unpack and start a local server

    unzip noshashi-continuity-browser.zip
cd noshashi-continuity-browser
python3 -m http.server 1430 --bind 127.0.0.1

    On Windows, use File Explorer to extract the ZIP, then run py -3 -m http.server 1430 --bind 127.0.0.1 from the extracted folder.

  3. Open the rehearsal

    Keep the terminal running and open http://127.0.0.1:1430/. The archive’s index.html launches the demo. The rehearsal uses the bundled data and needs no account or API keys.

Run from source

From the NOSHASHI repository root, install pinned dependencies once while online and start the dedicated Continuity development server.

npm ci
npm run continuity:dev

Open http://localhost:1430/continuity/demo/index.html for the rehearsal.

Validate and preview a production build locally 
npm run continuity:check
npm run continuity:test
npx vitest run tests/continuity-demo.test.js
npm run continuity:build
npm exec vite preview -- --config vite.continuity.config.mts --host 127.0.0.1 --port 1430 --strictPort

Stop the development server first if it is using port 1430. Then open http://127.0.0.1:1430/continuity/demo/index.html.

Data and review limits

Historical
The SOLO payment and RLUSD issuer snapshot come from archived public XRPL observations at the ledgers shown in each view.
Simulated
The wallet interaction, proposed payment and changed tag requirement use synthetic fixtures for the hypothetical Dfns workflow.
Live
The separate preflight workspace can attempt live, read-only XRPL queries. This rehearsal runs the recorded and simulated workflows.

Use the browser path for the rehearsal. Native installation and runtime need their own validation. Keep credentials and institution records out of the demo.
