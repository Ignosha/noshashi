Continuity: was each deposit credited exactly once?

Check one real Mainnet deposit against your own posted credits: right token, right issuer, right amount, credited once.

Transcript
  1. Continuity answers one question for an exchange, custodian or payments firm: was this deposit credited to the customer exactly once?
  2. It reads the payment from two Mainnet servers and compares it with the credits your own books posted.
  3. Here is a real issued-token payment read from Mainnet a moment ago, and one posted credit for it.
  4. In production, that credit comes straight from your accounting database through the read-only adapter.
  5. The transaction hash goes here. Press Verify, and both servers are asked for the same payment.
  6. Both servers agree. Every check is listed: validated, destination, issuer, currency, delivered amount, and exactly one matching credit.
  7. The report keeps the ledger index and hash, so an auditor can repeat the reading.
  8. Now suppose your books posted the same deposit twice: a double credit.
  9. Continuity fails it and says why: more than one credit matches this deposit. That is money paid out twice, caught before it leaves.
  10. Export evidence saves the full report as a file for your records.

  7. Plans run from two hundred and ninety-nine to three thousand five hundred dollars a month, all read-only.

For developers · 2

Developers: the Rippling Exposure API

Single-account checks, fleet scans of every wallet you run, and paged issuer holder scans, with API keys.

Transcript
  1. The Rippling Exposure API has three endpoints.
  2. GET v1 rippling, with an account, checks one account. Free, rate limited.
  3. POST v1 rippling batch takes a list of accounts and returns totals per currency across your whole fleet.
  4. GET v1 rippling issuer scans an issuer's holders, two hundred per call. Page on with offset until next offset is empty.
  5. Fleet and issuer scans need a key, sent as a Bearer token. The console accepts one and keeps it in this tab only.
  6. Without a key, the API answers four oh two, and says which plan unlocks the call. Your code can show that to the user.
  7. Each plan sets the per-minute limit, the batch size and how many holders an issuer scan reads.
  8. Keys are issued when the first invoice is paid. Every plan is read-only: no keys of yours, no signing, no custody.
